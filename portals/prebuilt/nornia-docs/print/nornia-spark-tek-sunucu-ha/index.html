Nornia Spark — Tek Sunucu Always-Up Docker HA & ISO Kurulumu

Nornia Spark; tek bir fiziksel sunucu veya sanal makine (VM) içinde Nornia'nın tüm bileşenlerini Docker konteynerlerine izole ederek çalıştıran, 2× Backend + 2× Frontend Aktif-Aktif yük dengeleme, Redis 7 küme veri yolu, MinIO S3 ses kayıt kasası ve sıfır kesintili (Zero-Downtime) güncelleme sunan Always-Up yüksek erişilebilirlik sürümüdür. Müşteri sahasına internet gerektirmeyen Air-Gapped Bootable ISO olarak da kurulabilir.

Başlamadan Önce Ön Koşullar
  • Mevcut tek sunuculu (PM2 + systemd) Nornia kurulumlarını kesinlikle bozmaz; tüm HA özellikleri ortam değişkenleri (REDIS_URL, S3_ENDPOINT, NORNIA_API_INTERNAL_URL) üzerinden opt-in olarak çalışır.
  • Minimum Donanım: 4 vCPU, 8 GB RAM, 120 GB NVMe/SSD (50–100 eşzamanlı çağrı). Önerilen Üretim Donanımı: 8 vCPU, 16 GB RAM, 250–500 GB NVMe.
  • İşletim Sistemi: Ubuntu 24.04 LTS (amd64) veya doğrudan üretilen Air-Gapped `nornia-spark-ha-v3.12.0.iso` kurulum medyası.
  • Güvenlik Duvarı Portları: TCP 80/443 (HTTPS), TCP 8089 (WebRTC WSS), UDP/TCP 5060–5061 (SIP), UDP 10000–20000 (RTP Medya).

3. Adım Adım Kurulum Sırası (Online Kurulum Scripti)

Temiz bir Ubuntu 24.04 LTS sunucusunda tek komutla tüm Nornia Spark kümesi, TLS sertifikası, kriptografik `.env` sırları ve UFW güvenlik duvarı kuralları otomatik yapılandırılır.

  1. 1Sunucuya SSH ile root olarak bağlanın ve proje deposunu `/opt/ai-project` altına çekin (veya mevcut depoyu güncelleyin).
  2. 2DNS kaydınızı (`pbx.firma.com`) sunucunun statik public IP adresine yönlendirin.
  3. 3`install_nornia_spark.sh` scriptini `--domain`, `--ip` ve (isteğe bağlı Let's Encrypt için) `--email` parametreleriyle çalıştırın.
  4. 4Script Docker Engine'i kurar, `/etc/nornia/certs/nornia.pem` sertifikasını üretir, 0600 izinli `/opt/ai-project/deploy/ha/.env` dosyasını kriptografik rastgele parolalarla oluşturur ve 8 konteyneri ayağa kaldırır.
  5. 5Kurulum sonunda `/api/system/ready` HTTP 200 doğrulamasını ve `http://127.0.0.1:8404/haproxy-stats` panelinden tüm backend'lerin UP olduğunu kontrol edin.
Nornia Spark — İlk Kurulum, Sağlık Doğrulama ve Zero-Downtime Güncelleme
# 1. İlk Kurulum (Let's Encrypt TLS dahil)
cd /opt/ai-project
sudo bash scripts/ha/install_nornia_spark.sh \
  --domain pbx.firma.com \
  --ip 203.0.113.10 \
  --email bt@firma.com

# 2. Derin Sağlık Kontrolü (HAProxy Readiness Probe)
curl -s http://127.0.0.1:8000/api/system/ready | jq .

# 3. Konteyner Durumlarını İzle
docker compose -f deploy/ha/docker-compose.spark.yml ps

# 4. Sıfır Kesintili (Zero-Downtime) Sürüm Güncelleme
#    (Önce backend-1/frontend-1 güncellenir ve READY beklenir; ardından 2. çift güncellenir)
sudo bash scripts/ha/install_nornia_spark.sh --update

4. Air-Gapped (İnternetsiz) Nornia Spark ISO Üretimi ve Müşteri Kurulumu

İnternet erişimi kısıtlı kurumsal müşteriler veya hızlı saha kurulumları için tüm Docker imajlarını ve Ubuntu 24.04 Autoinstall kurulumunu tek bir bootable ISO dosyasında paketleyebilirsiniz.

  1. 1Derleme makinesinde (`docker` ve `xorriso` kurulu Ubuntu sunucu) `build_nornia_ha_iso.sh --edition spark` komutunu çalıştırın.
  2. 2Script tüm Nornia Spark Docker imajlarını derleyip sıkıştırılmış `nornia-spark-images.tar.gz` arşivine alır ve Ubuntu 24.04 Live Server ISO içine Cloud-Init `autoinstall` ile gömer.
  3. 3Üretilen `dist/nornia-spark-ha-v3.12.0.iso` dosyasını müşterinin VMware ESXi / Proxmox / Hyper-V sunucusuna veya USB belleğe yazıp başlatın.
  4. 4İlk açılışta `nornia-firstboot.service` internet erişimine ihtiyaç duymadan tüm offline imajları Docker'a yükler ve Nornia Spark kümesini otomatik olarak ayağa kaldırır.
Kilit Güvenlik Notu — Mevcut Tek Sunucu Kurulumlarına Sıfır Etki
Nornia Spark'ta kullanılan REDIS_URL, S3_ENDPOINT, NORNIA_TRUSTED_INTERNAL_CIDRS ve NORNIA_INTERNAL_API_TOKEN değişkenleri yalnızca deploy/ha/.env içinde tanımlanır. Mevcut PM2 tabanlı sunucular bu değişkenler tanımlı olmadığı için birebir eski davranışında çalışmaya devam eder.
Nornia Spark Air-Gapped Bootable ISO Üretim Komutu
cd /opt/ai-project
sudo bash scripts/ha/build_nornia_ha_iso.sh \
  --edition spark \
  --version 3.12.0

Sık Karşılaşılan Hatalar & Sorun Giderme

Belirti: HAProxy /haproxy-stats ekranında backend-1 veya backend-2 DOWN görünüyor
Kök Neden: PostgreSQL henüz ayağa kalkmamış olabilir veya REDIS_PASSWORD / DATABASE_URL uyuşmazlığı nedeniyle `/api/system/ready` HTTP 503 dönüyordur.
Çözüm: `docker exec nornia-backend-1 curl -i http://127.0.0.1:8000/api/system/ready` komutuyla hangi alt kontrolün (`db_writable`, `redis`, `ami_connected`) hata verdiğini inceleyin.
Belirti: Asterisk dialplan CURL() çağrıları 401 Unauthorized dönüyor
Kök Neden: Docker köprü alt ağı `NORNIA_TRUSTED_INTERNAL_CIDRS` kapsamı dışında kalmıştır.
Çözüm: `deploy/ha/docker-compose.spark.yml` içinde `NORNIA_TRUSTED_INTERNAL_CIDRS` değerinin `127.0.0.1/32,172.16.0.0/12,10.0.0.0/8` içerdiğini doğrulayın ve backend konteynerlerini yeniden başlatın.
Belirti: WebRTC Web Phone 8089 WSS bağlantısında SSL hatası veriyor
Kök Neden: `/etc/nornia/certs/nornia.pem` self-signed sertifikadır ve tarayıcı henüz güvenmemiştir.
Çözüm: Üretim ortamında `--email` parametresiyle Let's Encrypt sertifikası alın veya kurumsal CA sertifikanızı fullchain+privkey birleşik formatında `/etc/nornia/certs/nornia.pem` dosyasına kopyalayıp `docker restart nornia-haproxy` çalıştırın.
